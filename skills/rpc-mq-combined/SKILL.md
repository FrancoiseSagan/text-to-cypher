# RPC 与 MQ 联合查询规范

## 1. 分解策略
不要试图把同步 RPC 与异步 MQ 塞进单个混乱的 `OPTIONAL MATCH` 导致笛卡尔积；应按通信机制拆分为两条子查询（在引擎复杂模式下独立执行后合并子图，或单语句中使用 `UNION ALL` 对齐列结构）：
- **子查询 A（同步 RPC 依赖）**：`MATCH p=(m:方法)-[:调用]->(d:下游API)-[:目标服务]->(target:微服务) WHERE m.moduleId = '<服务名>' RETURN ...`
- **子查询 B（异步 MQ 依赖）**：`MATCH p=(pub:方法)-[r1:消息流 {消息流类型: '发布至'}]->(ex:消息交换机)-[r2:消息流 {消息流类型: '路由至'}]->(q:消息队列)-[r3:消息流 {消息流类型: '消费自'}]->(sub:方法) WHERE pub.moduleId = '<服务名>' AND r1.路由键 = r2.路由键 RETURN ...`

## 2. 结果整合原则
- 明确标注每条依赖的 `依赖类型`（`RPC` 或 `MQ`）、`源服务`、`目标服务`、`通道或接口`（HTTP 路径或队列名）。
- 在复杂拆解模式下，每条子查询均应返回路径 `p`，以便后端基于 `elementId` 自动去重合并出完整的混合通信拓扑图。
